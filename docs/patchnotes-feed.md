# 패치노트 피드 계약 — 디스코드 → 런처

런처의 소식 탭은 두 공급원을 합쳐 보여준다: **디스코드 패치노트 피드**(위)와 **번들
카탈로그**(아래, 런처 자체 릴리스 노트). 이 문서는 피드 쪽 계약과 발행 절차를 고정한다.

## 피드 URL

```
https://play.fullmoon.ink/feeds/patchnotes.json
```

- 런처 코어(`src-tauri/src/news.rs`)가 부팅 후 `news_feed` 호출마다 이 URL을 먼저 친다.
- 3초 타임아웃. 실패 시 디스크 캐시(앱 데이터 `feeds/patchnotes.json`), 그다음 번들
  카탈로그로 열화한다. **빈 패널은 허용되지 않는다** — 네트워크가 죽었다는 것과
  "소식이 없다"는 다른 말이다.
- 성공하면 응답 전체를 캐시에 기록한다. 캐시는 네트워크 실패 시에만 읽는다.

## JSON 스키마

```json
{
  "news": [
    {
      "id": "pn-6",
      "tag": "update",
      "title": "패치노트 6 — 야생 시즌 1 밸런스",
      "summary": "몹 난이도 곡선과 드롭 테이블 조정. …",
      "date": "2026-09-01",
      "hue": 45,
      "featured": false,
      "url": "https://discord.com/channels/<guild>/<channel>/<message>"
    }
  ]
}
```

- `tag`: `"update" | "event" | "dev" | "cosmetic"` 중 하나.
- `hue`: 0–359. 뉴스 행 좌측 3px 스와치 색.
- `url`: 해당 패치노트 디스코드 메시지 링크. 런처는 이 값이 있으면 행을 클릭 가능하게
  만들고 `openExternal`로 연다. 없으면(번들 항목) 일반 텍스트 행.
- `id`: 피드 전체에서 고유. 런처는 id로 피드 항목과 번들 항목을 중복 제거하므로,
  봇이 발행하는 id는 `pn-<n>` 접두를 쓴다(번들은 `n< n>` — 충돌 없음).

## 발행 절차 (coin-bridge-bot — 미구현, 박스 작업)

1. 봇이 📋║풀문패치노트에 패치노트를 게시한 직후, 같은 내용으로 위 스키마의 JSON을
   만든다. `url`은 방금 올린 메시지 링크.
2. JSON을 박스의 웹 루트(`play.fullmoon.ink` 서비스 루트)에 `feeds/patchnotes.json`
   으로 기록한다. 기존 피드가 있으면 **앞에** 끼워 넣고 최대 30개로 잘라낸다.
3. 발행은 멱등하게: 같은 메시지를 재게시해도 id가 같으면 피드에 중복이 생기지 않는다.

런처 쪽(코어·캐시·폴백·UI 배지)은 구현돼 있다. 이 절차만 박스에 심으면 연동이 켜진다.
